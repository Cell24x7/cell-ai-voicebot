# Frontend source layout

| Folder               | Purpose                                                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `main.tsx`           | Entry: mounts `<App />`                                                                                                                                                                           |
| `App.tsx`            | Providers + router                                                                                                                                                                                |
| `app/`               | App-wide wiring: providers (theme, React Query, snackbar), query client, routes, router                                                                                                           |
| `pages/dev/`         | DEV-only tools (`/dev/realtime`) — routed only when `import.meta.env.DEV`, not in production builds                                                                                               |
| `pages/`             | Route-level pages — only compose features/components, no business logic                                                                                                                           |
| `features/system/`   | `useSystemInfo()` + `SystemInfoCard` (home page API status — proves API + proxy end to end)                                                                                                       |
| `features/`          | Feature folders (`auth/`, `contacts/`, `wallet/`, `flows/`, `calls/`…): components + hooks + API calls for that feature                                                                           |
| `components/`        | Shared, reusable UI components                                                                                                                                                                    |
| `layout/`            | App shell: sidebar, header, page layout (Phase 2)                                                                                                                                                 |
| `hooks/`             | Shared hooks                                                                                                                                                                                      |
| `services/api/`      | HTTP client (`client.ts` — every failure becomes an `ApiError`, `unwrap()` for envelopes), `errors.ts` (`ApiError`, `getErrorMessage`, `applyFieldErrors`), generated API types (`schema.gen.ts`) |
| `services/realtime/` | `/ws/events` client: `RealtimeClient`, `RealtimeProvider`, hooks `useWsStatus` / `useWsEvent` / `useWsTopic`, typed event map (keep in sync with websocket.md §5)                                 |
| `theme/`             | MUI theme (light + dark color schemes)                                                                                                                                                            |
| `types/`             | Shared TypeScript types                                                                                                                                                                           |
| `utils/`             | Generic helpers (formatting money, phones, dates…)                                                                                                                                                |
| `assets/`            | Static assets imported by code                                                                                                                                                                    |
| `test/`              | Test setup, `renderWithProviders`, `FakeWebSocket`                                                                                                                                                |

## Authentication (Phase 2)

- `features/auth/store.ts` (Zustand, **memory only**): `status` (`loading | authenticated | anonymous`), `session` (access token, user, account, role, permissions, impersonation), `savedSession` (superadmin session while impersonating).
- Page load: `AuthBootstrap` (root route) restores the session from the httpOnly refresh cookie (`POST /auth/refresh`).
- HTTP: `services/api/client.ts` adds `Authorization: Bearer …`; on `401 AUTH_TOKEN_EXPIRED / AUTH_UNAUTHENTICATED` it refreshes **once** (single-flight in the tab, Web Locks across tabs — rotating refresh tokens must never be used twice) and retries the request once; otherwise the user is signed out (`/login?next=…`).
- Guards: `RequireAuth`, `RedirectIfAuthed`, `RequirePermission perm|anyOf`, `RequirePlatformAdmin`; hooks `useSession`, `usePermission`, `useCan`, `useIsPlatformAdmin`.
- Realtime connects only while signed in (`getWsTicket` → `POST /ws/tickets`); `session.revoked` signs out, `user.updated` / `account.*` reload `/auth/me`.

## Query keys

`['<feature>', '<entity>', params?]`, defined in `features/<feature>/keys.ts` (e.g. `teamKeys.list(params)`). Signing out clears the whole cache.

## Rules

- Server state → React Query hooks inside the feature folder; no Redux ([ADR 0012](https://github.com/lalitbansal40/cell-ai-voicebot-backend/blob/main/docs/adr/0012-frontend-state.md)).
- Shared components go in `components/` only when used by 2+ features.
- Import with the `@/` alias (`@/theme`, `@/features/...`).
- Errors: use `ApiError` / `getErrorMessage()` / `applyFieldErrors()` — never read raw axios errors. 4xx are handled by the screen; unexpected errors (5xx, network, timeout) get a global toast automatically. Pass `meta: { silent: true }` when the screen shows the error itself.
- Queries retry only network / timeout / 5xx (max 2); mutations never retry.
- Realtime: subscribe with `useWsEvent(type, handler)` / `useWsTopic('call:<id>')` inside components; after a reconnect all queries are invalidated (missed events are not replayed).

## WhatsApp (Phase 9)

- **Foundation:** `services/api/whatsapp.ts` (`/whatsapp/*` + the dev simulator), `admin-whatsapp.ts` (superadmin), `meta-public.ts` (`/data-deletion` status); `features/whatsapp/` — `keys.ts`, `queries.ts` (`useWhatsAppConfig`, `useChannels` / `useChannel` polled every 5 s while a number is connecting / needs action, mutations that store the returned channel, `useWhatsAppLiveUpdates` for `whatsapp.channel.updated`), `permissions.ts` (`useCanManageWhatsApp`: `whatsapp.manage`, not impersonating, account active), `labels.ts` (statuses, quality, "1K / day" tiers, modes, sync statuses, error texts per code).
- **Embedded Signup:** `meta-sdk.ts` loads Meta's SDK once (15 s timeout, never in fake mode or tests) and parses `WA_EMBEDDED_SIGNUP` messages (origin-checked, safe JSON; any `FINISH*` is a finish); `embedded-signup.ts` (`runEmbeddedSignup` / `useEmbeddedSignup`: `FB.login` with `config_id`, `response_type: 'code'` and the coexistence feature type, the code sent at once, session ids awaited ≤ 3 s; outcomes finished / cancelled / error / popup blocked / SDK failed); fake mode: `TestSignupDialog` + `fake-signup.ts` (`fake.<base64url JSON>` codes with a nonce, session ids hashed like the backend fake).
- **Routes:** `/whatsapp` → `/whatsapp/numbers` (lazy, `whatsapp.read`), public `/data-deletion` (Meta's data deletion status page).
- **Numbers page** (`pages/whatsapp/WhatsAppPage.tsx` → `features/whatsapp/numbers/`): `NumbersPanel` (not-set-up / empty state with requirements / cards; `N of 10 numbers connected`; read-only hint for non-managers and impersonators), `ConnectWizard` ("Connect WhatsApp": kind of number with the coexistence warning → Meta's popup or the Test signup dialog → progress → Connected / Action needed / Needs reconnect / cancelled / error / pop-ups blocked; also Reconnect), `ChannelCard` (region "WhatsApp number <label>": status, quality, mode, limit, verified name + name status, billing line with the WhatsApp Manager link for customer-paid numbers, coexistence syncs + Retry sync, reason; Sync now, Retry setup, Enter PIN, Reconnect / Connect again, Rename, Disconnect with confirm), `ChannelDialogs` (Rename, Enter PIN), `ChannelDrawer` ("Number details": ids with copy, Meta statuses, token check, webhook health, history, dev-only **Send test event**), `texts.ts`.
- **Entry points:** superadmin account detail **WhatsApp** card (`features/admin/WhatsAppCard.tsx`, lazy: numbers with status / quality / who pays Meta, **Force disconnect** with a reason, **Manual connect** — token as a password field, never shown again —, **Meta billing** Platform credit line / Customer pays Meta with the irreversibility confirm); **Admin → WhatsApp setup** (`/admin/whatsapp`, `pages/admin/AdminWhatsAppPage.tsx`, lazy: provider, configured ✓ / ✗ flags — never values —, webhook / deauthorize / data deletion URLs with copy, last webhook, numbers by status, failed events + **Replay**); bell icons for the 6 WhatsApp notification types (links → `/whatsapp/numbers`); dashboard **WhatsApp** card (lazy: "Connect WhatsApp" for managers without a number, else "N connected · M need attention"); public `/data-deletion` page. Bundle: everything `index.html` loads, gzip — `main` 451.3 KB → 454.3 KB (+3.0 KB).

- **Foundation (T12.9):** `services/api/whatsapp-calling.ts` (`/whatsapp/channels/:id/calling` get / patch / sync, call permissions status + request, calls start with an Idempotency-Key / answer / decline / hold / transfer, media ticket, `PATCH /users/me/call-availability`), `calls.ts` filters `direction` / `mode`; WS events `whatsapp.call.incoming` / `taken` / `ended_ringing` / `call_permission.updated` and `provider` on `call.status` / `call.ended`; `features/whatsapp-calling/` — `keys.ts`, `queries.ts` (settings + mutations that store the answer, `useCallPermission` polled every 5 s while requested, `useRequestCallPermission`, `useCallingLiveUpdates` in the app shell), `permissions.ts` (`useCanCall` = `calls.trigger`, `useCanAnswer` = `calls.answer`, `useCanManageCalling` = `whatsapp.calling.manage`, `useCanRequestPermission` = `inbox.reply`; never while impersonating, account active), `labels.ts` (permission states, why-not reasons, unavailable reasons, Meta restrictions, routes, call outcomes, request states, error texts per code), `call-hours.ts` (mirror of the backend rules — both run `src/test/fixtures/call-hours-cases.json` —, HHMM ⇄ time input, today in a zone), `ProgramPicker` (published flow / active AI agent).
- **Number → Calling** (`settings/CallingSection.tsx` in the number drawer, `form.ts`): status + "Read again", unavailable explanation (coexistence, messaging limit < 2,000, not Cloud API, country), active Meta restrictions, business-call country note, the on / off switch with a confirm, call button visibility + countries, `CallHoursEditor` (time zone, week grid with ≤ 2 ranges a day, holidays that replace a day), callback permission, inbound route (team / AI / AI → team) with the AI program, ring time and ring list (people who can answer), permission request text; only changed fields are sent; owners / admins edit, everyone else reads.
- **Contact panel** (`panel/CallingPanelSection.tsx`): permission chip + "Can call until …" (account time zone), why not, next request time, permission history, last 5 WhatsApp calls, **Ask to allow calls** (`RequestPermissionDialog`: the number's text, editable inside the 24-hour window; outside it the approved template is explained).
- **Chat bubbles** (`bubbles.tsx`): permission request with its state and the answer, the customer's reply (allowed for 7 days / always / declined, "after calling you" for callback permission), the "Call us" button message, call bubbles ("Call · 2:14", "Missed call", "AI call · 0:45") linking to the call; texts stay plain text.
- **Call experience (T12.10, `live/`):** `store.ts` (zustand: the one live WhatsApp call of this browser + ringing calls), `controller.ts` (`placeCall` — microphone, `POST /whatsapp/calls` with one Idempotency-Key per click, the Phase 7 audio engine + `/ws/media` —, `answerCall` (first wins), `declineCall`, `takeOver` (supervisors: transfer the AI call to themselves, then answer), mute / hold / keys / hang up, `reconnectCall` with a new media ticket, account `call.status` / `call.ended` for AI calls; mic / engine / socket / API injectable), `CallButton` (chat header + contact panel: Request permission · Requested · waiting · Call → Call yourself / Call with AI · Can't call + reason; hidden without `calls.trigger`), `CallWithAiDialog` (program + "About ₹X a minute (call + AI)" from `/wallet/rates`, `cost.ts`), `CallMounts` (always in the app shell, tiny: forwards call events, lazy-loads `CallBar` — label, state / timer, recording dot, network, mute, hold, keypad, hang up, "AI is talking" + Take over, Reconnect, Close — and `IncomingPopup` — label + number, Accept / Decline, "Taken by …", "stopped ringing", ring sound with an off switch, a background browser notification asked once —, `ringer.ts`), `AvailabilityToggle` in the header (Available / Busy / Offline, "On a call" while on one; `calls.answer` only). `CallMounts` and the toggle are lazy (after the shell renders), so the start bundle grows only +1.4 KB (JS as one gzip stream).
- **Screens (T12.11):** Calls list — **WhatsApp** badge, **Type** column (Incoming / Outgoing · Team member / AI), Direction + Answered-by filters when Line = WhatsApp; call detail — region **WhatsApp** (`CallWhatsAppDetails`: who called, who talked / answered / took over, WhatsApp's talk time, the chat link, Meta's timeline in words) and "Free (the customer called)" for incoming calls; wallet — ledger lines **WhatsApp call · India · 2:14**, **WhatsApp call prices** (`WhatsAppCallPrices`, selling price per minute); superadmin WhatsApp billing — **Calling rates** tab (`CallingRatesTab`: the card in force with tiers, CSV import with row errors + per-minute diff, effective date + note, edit one market, history), **WhatsApp call prices** in Settings (markup, fee per minute, hold / extension minutes), margin rows **WhatsApp calls**; 5 calling notification icons; dashboard WhatsApp card **Today: N WhatsApp calls · M missed** (`calls.read`, calling on).

Calling recovery: `live/queries.ts` polls active call status every 2 seconds and stops at a final state. The shell forwards permission/settings events and invalidates conversation-keyed contact panels. `controller.ts` invalidates canceled async work, releases late streams and media on end/unmount, and handles hold / low-wallet notices. `MicrophonePicker` switches the capture input through the existing audio graph without replacing the call socket.
